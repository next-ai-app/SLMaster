# sl_edu — Structured-Light 3D Scanning Teaching Kit

A pure-Python (numpy + OpenCV) re-implementation of SLMaster's core pipeline,
built for **learning**: every stage is short, readable, and verifiable against
the C++ original. AGPL-3.0 (derived from SLMaster).

## Layout

```
sl_edu/            importable package (the "answer key")
  patterns.py      sinusoidal + shifted-gray-code generation (faithful port)
  decode.py        wrapped phase -> floor map -> absolute phase
  oracle.py        data/ loaders + C++ golden-value anchors
  calibrate.py     cv2 camera/stereo calibration wrappers
  reconstruct.py   triangulate / depth_from_phase (reverseCamera port) / PLY
  backends.py      PyOpenCvCamera + PyMonitorProjector (virtual mode included)
tests/             pytest suite incl. C++ golden values on the real dataset
notebooks/         7-lesson course (generated by build_notebooks.py)
```

## Quickstart

```bash
cd edu
uv venv --python 3.12 .venv        # open3d needs <=3.12
uv pip install -e ".[dev]" --python .venv/bin/python
.venv/bin/python -m pytest tests/              # 18 tests, ~5s
.venv/bin/python -m jupyter lab notebooks/     # or: nbconvert --execute
```

Regenerate notebooks after editing the generator:
`python notebooks/build_notebooks.py`

## The 7 lessons

| NB | Topic | Hardware |
|---|---|---|
| 01 | Pattern generation (phase shift + gray code) | none |
| 02 | Capture, confidence, virtual projector loop | none |
| 03 | Phase decoding (with C++ golden anchors) | none |
| 04 | Calibration (synthetic chessboard + real caliInfo.yml) | none |
| 05 | Triangulation → real point cloud from data/shiftGraycode | none |
| 06 | Live scan (virtual by default; webcam + 2nd monitor optional) | optional |
| 07 | Correctness vs the C++ oracle + performance discussion | none |

## Verification philosophy

- **Golden anchors**: C++ gtest asserts specific pixel values on the shipped
  dataset (e.g. `floor[453][700]==17`, `unwrap[460][653]==103.75`). The Python
  suite asserts the SAME values — pixel-exact cross-language equivalence.
- **Documented divergences** (not bugs): ±1px tie at wrap boundaries (atan2
  numerator is numerically zero there) and the right-edge gray-code wrap
  artifact. Both exist in the C++ implementation.
- `cv2.structured_light` uses a different pattern convention than SLMaster —
  interesting for discussion (nb07), not usable as an oracle.

## Known notes

- macOS camera permission: grant Terminal/IDE in System Settings → Privacy.
- open3d wheels currently require Python ≤ 3.12.
- Full-frame `depth_from_phase` is a teaching double-loop (minutes); crop an
  ROI like nb05 does, or port to the C++ SIMD path for speed.
